Your supervisor sent back the PDF with forty-seven marks on chapter 3. proofback reads them and tells you, for each one, the file, line and characters in your LaTeX it refers to. Then it keeps a record of what you changed, what you won’t change and why, and writes the replies back into the reviewer’s own PDF.

    1Method

    Four commands cover a review round. Each one also takes --json, so a script or an agent can drive it.

    proofback import review-ch3.pdf
    Reads every annotation in the file. Acrobat, Preview, Zotero, Okular and tablet apps all store them a little differently; proofback knows the differences.
    proofback list
    SyncTeX, the file LaTeX writes next to your PDF, narrows each mark down to a few source lines. An aligner that understands \ref, macros, ligatures and hyphenation then finds the characters. Every item carries its confidence: exact, line, region or page.
    proofback patch, resolve
    “Replace with robust” becomes a diff you read before applying. A question gets a reply. A suggestion you disagree with gets a reason. It is all saved in .proofback/ next to your sources, so it goes into git with them and follows your edits into the next draft.
    proofback answer, letter
    The reviewer gets their own PDF back with your reply under each of their notes. Journals get a response letter built from the same record.

    2Inputs

    Nobody has to install anything or make an account to review your work. They keep doing what they already do.

    The reviewer sendsCommandWhat happens
    An annotated PDFimport review.pdfHighlights, underlines, strike-outs, carets, sticky notes, free text and ink. Reply threads and author names are kept.
    An email with page numbersimport notes.txtLines like “p. 12, para 2: unclear” are located in the source. You confirm each one before it counts.
    A Word filedocx exportSend a DOCX with hidden source markers. Their tracked changes and comments map back to the exact lines.
    A PDF of a Typst documentimport paper.pdfSame as LaTeX, through the Typst compiler built into proofback.

    3Agents

    If you work with Claude Code, Cursor or another coding agent, proofback mcp gives it the items with their source ranges. It can propose a patch and draft a reply. You still decide.

    Two rules are enforced in the tool, not left to the prompt. An edit can’t be marked done unless the text it points at has actually changed. A comment can’t be marked done without a reply. Reviewer text reaches the agent labelled as untrusted, so a note that says “ignore your instructions” is just a note.

    proofback itself makes no network calls. The optional suggest command is off until you turn it on and shows exactly what it would send.

    4Results

    We generate theses and papers, annotate them the way real PDF apps do, and check where every mark lands. This runs on every pull request. If wrong placements go above 1% or exact matches drop below 90%, the change doesn’t merge.
