    How it works

    proofback import review-ch3.pdf
    Reads every annotation in the PDF, whichever app made it: Acrobat, Preview, Zotero, Okular, PDF Expert, an iPad.
    proofback list
    SyncTeX narrows each mark to a few lines. A TeX-aware aligner then finds the exact characters, through \ref, macros, ligatures and hyphenation. Each item says how sure it is.
    proofback patch, resolve
    Mechanical edits become a diff you can review. Questions get replies. Items you won't change get a reason. Everything is saved in .proofback/ and follows your edits into the next draft.
    proofback answer, letter
    Send the reviewer their own PDF back with your reply on every note, or a response letter built from the same data.

    What reviewers can send

    The reviewer keeps using whatever they already use. No accounts, no uploads.

    Annotated PDFv0.1Highlights, underlines, strike-outs, carets, notes, free text, ink. Replies and authors kept.
    Notes in an emailv0.5“p. 12, ¶2: unclear”. Parsed, located, and confirmed by you before anything changes.
    Word documentv0.6Exported with hidden source anchors, so tracked changes and comments map back precisely.

    Works with coding agents

    The core is plain, repeatable code that runs offline. Agents use it through an MCP server: they get each item with its source range and context, propose a patch, and record a reply.

    An agent can't mark an item done unless the text it points to has actually changed. Every command has --json output and a published schema. Built-in AI suggestions are optional and use your own model.

    Accuracy, measured every release

    CI builds a set of realistic theses and papers, annotates them the way each PDF app actually writes annotations, and checks where proofback lands. A release that does worse than the last one doesn't ship. The first numbers arrive with v0.1.
